# Метод и источники

## Что анализировалось

| Файл | Роль | SHA-256 |
|---|---|---|
| `Heroes3.exe` | Исполняемый файл игры, GOG Heroes III Complete (движок Shadow of Death 3.2). База образа `0x400000`, около 13 300 функций. | `057c9d88e7206f6669a4615de2c6e02ab6c4e2d570a9e2badf07fe0bd6247274` |
| `H3bitmap.lod`, `H3ab_bmp.lod` | Архивы с текстовыми таблицами, которые движок читает при запуске (`CRTRAITS.TXT`, `HCTRAITS.TXT`, `SPTRAITS.TXT`, `CRBANKS.TXT`, …) | |
| `HotA.dll`, `HotA.dat` | Horn of the Abyss 1.8.1, используется только в главе об отличиях HotA | |

В исполняемом файле нет отладочных символов. Имена функций и полей на этих страницах придуманы нами. Адреса даны как виртуальные адреса в неизменённом `Heroes3.exe`: с тем же файлом любой может открыть то же место в дизассемблере.

Инструменты: Ghidra 12.1 для декомпиляции, небольшие скрипты на Python для архивов. Скрипты лежат в [репозитории](https://github.com/PashaPash/hmm3docs/tree/main/tools). Файлы игры здесь не распространяются.

## Метки достоверности

| Метка | Значение |
|---|---|
| **[code `0x…`]** | Прочитано в декомпилированной функции по этому адресу. |
| **[data `FILE.TXT`]** | Значение взято из таблицы данных игры. |
| **[inferred]** | Следует из прочитанного кода или данных, но путь не прослежен от начала до конца. |
| **[unverified]** | Общеизвестное утверждение об игре, пока не подтверждённое по бинарнику. |

Статический анализ показывает, что делает код, но не то, как часто ветка срабатывает в реальных партиях. Если правило дополнительно проверено в запущенной игре, это указано на странице.

## Границы

За основу взят неизменённый исполняемый файл Shadow of Death. HD-мод и Horn of the Abyss меняют код движка в памяти во время работы; их поведение описано только в главе про HotA и только там, где оно подтверждено.

Названия существ, заклинаний и навыков в таблицах пока даны по-английски, как в файлах данных.
